Introduction — the whole ecosystem

Introducción — el ecosistema completo

The problem this system solves

El problema que resuelve este sistema

Most design systems get built backwards: someone draws a Button, someone else codes it, and then everyone argues about what it should have been. The result is a library full of components that work but disagree — different prop names for the same idea, different token names for the same colour, no record of why anything is the way it is.

Cristian's system runs the other way. Nothing gets built until a decision exists. Nothing gets decided until evidence exists. The sequence is strict:

La mayoría de los sistemas de diseño se construyen al revés: alguien dibuja un Button, otra persona lo codifica, y luego todos discuten sobre cómo debería haber sido. El resultado es una librería llena de componentes que funcionan pero no se hablan entre sí — diferentes nombres de props para la misma idea, diferentes nombres de tokens para el mismo color, sin registro de por qué las cosas son como son.

El sistema de Cristian va en sentido contrario. Nada se construye hasta que existe una decisión. Nada se decide hasta que existe evidencia. La secuencia es estricta:

Explore → Report → Decide → Build Explorar → Reportar → Decidir → Construir

This is not a philosophy. It is enforced by the tools: the build fails if a contract contradicts the code, CI fails if the prop glossary drifts, and the ADR index fails if a decision isn't recorded. You cannot skip steps and have a green build.

Esto no es una filosofía. Está forzado por las herramientas: el build falla si un contrato contradice el código, CI falla si el glosario de props se desvía, y el índice de ADR falla si una decisión no está registrada. No puedes saltarte pasos y tener un build verde.

The five layers

Las cinco capas

1

Brand & Tokens

Marca y Tokens

Brand decisions → Primitives → Semantic roles → Component slots. Files: tokens/*.json → Style Dictionary → build/*.css + *.ts. CSS custom properties flow downstream.

Decisiones de marca → Primitivos → Roles semánticos → Slots de componente. Archivos: tokens/*.json → Style Dictionary → build/*.css + *.ts. Las propiedades CSS custom fluyen aguas abajo.

2

Contracts — the product

Contratos — el producto

One JSON file per component. Framework-agnostic. Declares: purpose, behaviour, anatomy, states, axes, a11y commitments, token policy per part. File: contracts/components/<Name>/<Name>.contract.json.

Un archivo JSON por componente. Agnóstico de framework. Declara: propósito, comportamiento, anatomía, estados, ejes, compromisos de accesibilidad, política de tokens por parte. Archivo: contracts/components/<Nombre>/<Nombre>.contract.json.

3

Inherited conventions & namespace

Convenciones heredadas y namespace

The shared vocabulary every component must speak. Props Map validates that no component coins a synonym. Files: contracts/prop-canon.json (hand-maintained canon), .ai/maps/prop-map.md (measured reality, generated).

El vocabulario compartido que todo componente debe hablar. El Props Map valida que ningún componente acuñe un sinónimo. Archivos: contracts/prop-canon.json (canon manual), .ai/maps/prop-map.md (realidad medida, generado).

4

Component — logic + styles

Componente — lógica + estilos

The contract builds two things in parallel: Logic (.tsx — CVA variant axes, state tracking) and Styles (.module.css — token variables applied). Together they generate the Component API. React binding: react/bindings/<Name>.react.json.

El contrato construye dos cosas en paralelo: Lógica (.tsx — ejes de variantes CVA, seguimiento de estado) y Estilos (.module.css — variables de tokens aplicadas). Juntas generan la API del componente. Binding React: react/bindings/<Nombre>.react.json.

5

Artifacts

Artefactos

Three outputs — all generated from the contract, never authored by hand: coded component (packages/react/dist/), Figma component (wired via .figma/ manifest), component docs (Storybook or custom).

Tres salidas — todas generadas desde el contrato, nunca escritas a mano: componente codificado (packages/react/dist/), componente Figma (conectado vía .figma/), documentación del componente (Storybook o custom).

Design decisions loop back. When a decision changes, it modifies the contract → contract modifies logic + styles → artifacts regenerate. Nothing skips the chain.

Las decisiones de diseño forman un bucle. Cuando una decisión cambia, modifica el contrato → el contrato modifica lógica + estilos → los artefactos se regeneran. Nada se salta la cadena.

The AI layer

La capa de IA

MCP — Model Context Protocol

The protocol that lets an AI agent call external tools. The main connection here is Figma — the agent reads the design file, inspects variables, gets component structure, without a human copy-pasting screenshots.

Agent

A model (Claude) that uses MCP tools to take actions: read the Figma file, write a research doc, propose a contract, run the verify gate. The agent does not make decisions — it surfaces evidence and executes recorded decisions.

Skill (procedure)

A reusable prompt + instruction set. This repo ships five skills in .claude/skills/: ds-decide, ds-component (retired), ds-figma-explain, ds-figma-document, ds-figma-component.

Context window & progressive disclosure

The agent has limited working memory. The system is designed so nothing is loaded up front — only the doc governing the surface being touched. Every README is small. Every ADR is narrow. Load on demand.

MCP — Model Context Protocol

El protocolo que permite a un agente de IA llamar herramientas externas. La conexión principal aquí es Figma — el agente lee el archivo de diseño, inspecciona variables, obtiene la estructura de componentes, sin que un humano copie y pegue capturas de pantalla.

Agente

Un modelo (Claude) que usa herramientas MCP para tomar acciones: leer el archivo de Figma, escribir un doc de investigación, proponer un contrato, ejecutar el gate de verificación. El agente no toma decisiones — saca evidencia a la superficie y ejecuta decisiones registradas.

Skill (procedimiento)

Un conjunto reutilizable de prompt + instrucciones. Este repo incluye cinco skills en .claude/skills/: ds-decide, ds-component (retirado), ds-figma-explain, ds-figma-document, ds-figma-component.

Ventana de contexto y divulgación progresiva

El agente tiene memoria de trabajo limitada. El sistema está diseñado para que nada se cargue de antemano — solo el doc que governa la superficie que se está tocando. Cada README es pequeño. Cada ADR es estrecho. Carga bajo demanda.

The five traps

Las cinco trampas

DriftDeriva

When source of truth and code disagree. A Figma component says one thing; the coded component does another. Gates verify:contract and prop-map:check exist to detect this automatically.

Cuando la fuente de verdad y el código no coinciden. Un componente de Figma dice una cosa; el codificado hace otra. Los gates verify:contract y prop-map:check existen para detectarlo automáticamente.

Single source of truthFuente de verdad única

Every fact lives in exactly one place. Tokens in tokens/, prop names in prop-canon.json, component spec in the contract. Two copies guarantees eventual disagreement.

Cada hecho vive en exactamente un lugar. Tokens en tokens/, nombres de props en prop-canon.json, especificación en el contrato. Dos copias garantizan desacuerdo eventual.

Variant is not a propLa variante no es un prop

A visual variant (size, hierarchy) is an axis. A state (disabled, loading) is a state. Mixing them produces broken accessibility trees — the platform already owns disabled.

Una variante visual (size, hierarchy) es un eje. Un estado (disabled, loading) es un estado. Mezclarlos produce árboles de accesibilidad rotos — la plataforma ya posee disabled.

Measure, don't eyeballMide, no calcules a ojo

A research doc records numbers, not adjectives. "41 variables across 3 collections" is evidence. "Quite a lot of variables" is noise. Adjective-based decisions cannot be re-evaluated.

Un doc de investigación registra números, no adjetivos. "41 variables en 3 colecciones" es evidencia. "Bastantes variables" es ruido. Las decisiones basadas en adjetivos no pueden re-evaluarse.

Generated / validated / reviewedGenerado / validado / revisado

Generated — consistent with its inputs; inputs may be wrong. Validated — legal against a schema; legal ≠ true. Reviewed — a person verified it describes reality. Only reviewed catches a plausible-but-wrong claim. That part is always on you.

Generado — consistente con sus entradas; las entradas pueden estar mal. Validado — legal contra un esquema; legal ≠ verdadero. Revisado — una persona verificó que describe la realidad. Solo revisado atrapa una afirmación plausible pero incorrecta. Esa parte siempre es tuya.

Core arc

Arco central

Explore → Report → Decide → Build

Explorar → Reportar → Decidir → Construir

The four steps Cristian teaches. You do not draw a Button first. You read the design source, write down what is measurably there (a report), turn open questions into recorded decisions (ADRs), then build the component against a decision that already exists.

Los cuatro pasos que enseña Cristian. No dibujas un Button primero. Lees la fuente de diseño, escribes lo que está mediblemente ahí (un reporte), conviertes las preguntas abiertas en decisiones registradas (ADRs), luego construyes el componente contra una decisión que ya existe.

Design source

Fuente de diseño

The Figma file we read from. In our case: the "Kraken DS" file. It is a canvas to read, not a pipeline stage — nothing in Figma is auto-swept into code.

El archivo de Figma del que leemos. En nuestro caso: el archivo "Kraken DS". Es un lienzo para leer, no una etapa de pipeline — nada en Figma se barre automáticamente hacia el código.

Governance

Gobernanza

ADR — Architectural Decision RecordRegistro de Decisión Arquitectónica

A short markdown file that records a decision, why it was made, and alternatives considered. Lives in docs/ADR/. Once accepted, other work must respect it or update it — silently ignoring one is a defect.

Un archivo markdown corto que registra una decisión, por qué se tomó, y las alternativas consideradas. Vive en docs/ADR/. Una vez aceptado, otro trabajo debe respetarlo o actualizarlo — ignorarlo silenciosamente es un defecto.

Decision vs contract

Decisión vs contrato

An ADR is the decision (agnostic, high-level). A contract is its mechanical realisation (schemas, JSON files, scripts) that lives next to the code. The ADR links its contracts. This lets a decision stay stable while its implementation moves.

Un ADR es la decisión (agnóstica, de alto nivel). Un contrato es su realización mecánica (esquemas, archivos JSON, scripts) que vive junto al código. El ADR enlaza sus contratos. Esto permite que una decisión se mantenga estable mientras su implementación se mueve.

Draft vs Accepted

Draft vs Accepted (estado del ADR)

Pre-v0, most ADRs stay Draft. An ADR only becomes Accepted once the code that realises it exists. After v0, supersede old ADRs instead of editing them.

Pre-v0, la mayoría de los ADRs se mantienen en Draft. Un ADR solo se convierte en Accepted una vez que el código que lo realiza existe. Después de v0, se superseden los ADRs viejos en lugar de editarlos.

Component vocabulary

Vocabulario de componentes

Contract (component contract)

Contrato (contrato de componente)

A <Name>.contract.json file for each component. States what source code cannot state: which HTML element renders, where the ref lands, what a slot accepts, accessibility commitments, and which family of token is allowed to paint which channel of which node.

Un archivo <Nombre>.contract.json para cada componente. Declara lo que el código fuente no puede declarar: qué elemento HTML renderiza, dónde aterriza la ref, qué acepta un slot, compromisos de accesibilidad, y qué familia de token puede pintar qué canal de qué nodo.

Prop glossary

Glosario de props

Generated file (.ai/maps/prop-map.md) listing every prop used across the system, its type, and where it appears. Descriptive, not prescriptive. Hand-editing it fails CI.

Archivo generado (.ai/maps/prop-map.md) que lista cada prop usado en todo el sistema, su tipo, y dónde aparece. Descriptivo, no prescriptivo. Editarlo a mano falla CI.

Slot

A place inside a component where the user (of the component) passes content — typically children, or a named slot like leadingIcon.

Un lugar dentro de un componente donde el usuario (del componente) pasa contenido — típicamente children, o un slot nombrado como leadingIcon.

Part

Parte

A named piece of a component that renders. Contracts name the parts so gates can check nothing is claimed that does not actually render.

Una pieza nombrada de un componente que renderiza. Los contratos nombran las partes para que los gates puedan verificar que nada se afirma que no renderiza realmente.

Axis / variant

Eje / variante

An axis is a dimension of variation (size, tone, intent). Its values are the variants (sm | md | lg). Contracts declare the axes; the source must implement exactly those values.

Un eje es una dimensión de variación (size, tone, intent). Sus valores son las variantes (sm | md | lg). Los contratos declaran los ejes; el código fuente debe implementar exactamente esos valores.

CVA — Class Variance Authority

A tiny library used to bind variant names to CSS classes in a type-safe way. This library uses CVA + CSS Modules.

Una pequeña librería usada para vincular nombres de variantes a clases CSS de manera type-safe. Esta librería usa CVA + CSS Modules.

CSS Modules

CSS files scoped to a component. Class names get hashed at build time so they cannot collide with other components' classes.

Archivos CSS con alcance a un componente. Los nombres de clase se hashean en tiempo de build para que no puedan colisionar con las clases de otros componentes.

Tokens & the pipeline

Tokens y el pipeline

Token

A named design value: a colour, a spacing step, a font size. Not a raw hex — a reference to a value that has a meaning. --kraken-color-bg-primary is a token; #0f172a is a value.

Un valor de diseño nombrado: un color, un paso de espaciado, un tamaño de fuente. No un hex crudo — una referencia a un valor que tiene un significado. --kraken-color-bg-primary es un token; #0f172a es un valor.

Primitive vs semantic token

Primitivo vs token semántico

Primitive: raw palette (color-neutral-900). Semantic: what it means in context (color-bg-primary). Semantic tokens reference primitives. Components consume semantic tokens.

TierExampleReferences
Primitive--ds-color-indigo-500: #5146e6nothing — it is a literal
Semantic role--ds-color-brand-primary → var(--ds-color-indigo-500)primitives only
Component slot--ds-color-fill-loud → var(--ds-color-brand-primary)semantic roles only

Components style against semantic roles only — never against branded families. This is what makes every variant "free": changing what --ds-color-fill-loud points to re-themes every component that uses it.

Primitivo: paleta cruda (color-neutral-900). Semántico: lo que significa en contexto (color-bg-primary). Los tokens semánticos referencian primitivos. Los componentes consumen tokens semánticos.

NivelEjemploReferencias
Primitivo--ds-color-indigo-500: #5146e6nada — es un literal
Rol semántico--ds-color-brand-primary → var(--ds-color-indigo-500)solo primitivos
Slot de componente--ds-color-fill-loud → var(--ds-color-brand-primary)solo roles semánticos

Los componentes se estilizan contra roles semánticos únicamente — nunca contra familias de marca. Esto es lo que hace que cada variante sea "gratis": cambiar a qué apunta --ds-color-fill-loud re-temea cada componente que lo usa.

DTCG — Design Tokens Community Group

The spec for the JSON format tokens are written in. {"$type": "color", "$value": "#0f172a"} is DTCG. The industry-standard shape.

La especificación para el formato JSON en que se escriben los tokens. {"$type": "color", "$value": "#0f172a"} es DTCG. La forma estándar de la industria.

Style Dictionary

The tool that reads DTCG JSON and writes it out as CSS custom properties, TS constants, or any other target. The pipeline between token JSON and what a component consumes.

La herramienta que lee JSON DTCG y lo escribe como propiedades CSS custom, constantes TS, u otro objetivo. El pipeline entre el JSON de tokens y lo que un componente consume.

CSS custom property

Propiedad CSS custom

--kraken-color-bg-primary: #0f172a;. Native browser feature. Tokens compile to these; components use var(--kraken-color-bg-primary).

--kraken-color-bg-primary: #0f172a;. Característica nativa del navegador. Los tokens compilan a estas; los componentes usan var(--kraken-color-bg-primary).

Upstream / downstream

Upstream = what your DS depends on (NativeWind, Phosphor icons). Downstream = what depends on your DS (consumer apps). The DS lives in the middle: extends upstream, feeds downstream.

Upstream = de lo que depende tu DS (NativeWind, íconos Phosphor). Downstream = lo que depende de tu DS (apps consumidoras). El DS vive en el medio: extiende el upstream, alimenta el downstream.

Repo shape

Estructura del repositorio

Monorepo

One repository holding many packages. Ours holds @kraken/tokens, @kraken/react, @kraken/contracts, plus apps/sandbox and apps/storybook.

Un repositorio que contiene muchos paquetes. El nuestro contiene @kraken/tokens, @kraken/react, @kraken/contracts, más apps/sandbox y apps/storybook.

pnpm workspace

The mechanism that lets packages inside a monorepo reference each other by name without publishing anywhere.

El mecanismo que permite a los paquetes dentro de un monorepo referenciarse entre sí por nombre sin publicar en ningún lado.

Scope (npm scope)

Scope (alcance npm)

The @kraken in @kraken/react. Namespaces the package. Set once by pnpm init-ds kraken — cannot be safely renamed by hand later.

El @kraken en @kraken/react. Da namespace al paquete. Se establece una vez con pnpm init-ds kraken — no se puede renombrar de forma segura a mano después.

Sandbox

apps/sandbox — a fast Vite page that boots in ~1s, pointed directly at component source. For rapid, single-component work.

apps/sandbox — una página Vite rápida que arranca en ~1s, apuntando directamente al código fuente del componente. Para trabajo rápido, componente a componente.

Storybook

apps/storybook — the classic component gallery. Present on disk but deliberately not installed by default. One line to switch on.

apps/storybook — la galería clásica de componentes. Presente en disco pero deliberadamente no instalada por defecto. Una línea para activarla.

Gates & CI

Gates y CI

Gate

Gate (compuerta)

An automated check that fails the build if broken. pnpm verify runs every gate locally; CI runs them again. A gate that only runs locally is not a gate.

Una verificación automatizada que falla el build si se rompe. pnpm verify ejecuta cada gate localmente; CI los ejecuta de nuevo. Un gate que solo corre localmente no es un gate.

Report (vs gate)

Reporte (vs gate)

A check that reports findings without failing. Uncontracted components and paint findings are reports, not gates — because a gate that fails on everything day one gets switched off, and a switched-off gate protects nothing.

Una verificación que reporta hallazgos sin fallar. Los componentes sin contrato y los hallazgos de paint son reportes, no gates — porque un gate que falla en todo el día uno se apaga, y un gate apagado no protege nada.

CI — Continuous IntegrationIntegración Continua

The remote pipeline (GitHub Actions) that runs the gates on every push. If CI is green, the change is safe to land.

El pipeline remoto (GitHub Actions) que ejecuta los gates en cada push. Si CI está verde, el cambio es seguro para aterrizar.

Cristian's jargon

Lo que dice Cristian que parece jerga

"Contracts vs libraries"

"Contratos vs librerías"

The contract layer is more important than the library that implements it. Two libraries can implement the same contract; the contract is what stays stable.

La capa de contratos es más importante que la librería que la implementa. Dos librerías pueden implementar el mismo contrato; el contrato es lo que se mantiene estable.

"Derivation chain"

"Cadena de derivación"

The chain from brand decisions → primitive tokens → semantic tokens → component styles → app usage. Every step is downstream of a decision made one level up.

La cadena desde decisiones de marca → tokens primitivos → tokens semánticos → estilos del componente → uso en la app. Cada paso está aguas abajo de una decisión tomada un nivel arriba.

"Axes registry"

"Registro de ejes"

The central list of allowed axes (size, tone, intent) with allowed values. Prevents each component from inventing its own vocabulary.

La lista central de ejes permitidos (size, tone, intent) con valores permitidos. Evita que cada componente invente su propio vocabulario.

"Variant ≠ status"

"Variante ≠ estado"

A variant is a visual axis (a Button can be size=lg). A status is a runtime state (disabled, loading). They must not be mixed — they behave differently in accessibility trees.

Una variante es un eje visual (un Button puede ser size=lg). Un estado es una condición en tiempo de ejecución (disabled, loading). No deben mezclarse — se comportan diferente en los árboles de accesibilidad.

"Prop ownership"

"Propiedad propia del prop"

For any prop, exactly one place owns its definition. Copying a prop definition into another component is a defect — reuse it or contract it.

Para cualquier prop, exactamente un lugar posee su definición. Copiar una definición de prop en otro componente es un defecto — reutilízala o contrátala.

File formats

Formatos de archivo

.md — Markdown

Plain text with lightweight formatting. Not code — just writing. Every README, ADR, and GLOSSARY is Markdown. Renders as formatted docs on GitHub.

Texto plano con formato ligero. No es código — solo escritura. Cada README, ADR y GLOSARIO es Markdown. Se renderiza como docs formateados en GitHub.

.json — JSON

Structured data: keys and values, no logic, no functions. In this repo JSON is doing heavy lifting: package.json (project identity), ds.config.json (brand), *.contract.json (component spec), *.react.json (React binding), prop-canon.json (canonical prop names).

Datos estructurados: claves y valores, sin lógica, sin funciones. En este repo JSON hace mucho trabajo: package.json (identidad del proyecto), ds.config.json (marca), *.contract.json (especificación del componente), *.react.json (binding React), prop-canon.json (nombres de props canónicos).

.ts — TypeScript

JavaScript with types. You declare what kind of data a variable holds; the compiler catches mistakes before the code runs. Used for all library code in packages/react/src/ and config files like vite.config.ts.

JavaScript con tipos. Declaras qué tipo de dato contiene una variable; el compilador captura errores antes de que el código corra. Usado para todo el código de librería en packages/react/src/ y archivos de config como vite.config.ts.

.tsx — TypeScript + JSX

TypeScript that also contains HTML-like syntax (JSX) for writing React components. Lets you write <Button size="m" /> directly in TypeScript.

TypeScript que también contiene sintaxis HTML-like (JSX) para escribir componentes React. Permite escribir <Button size="m" /> directamente en TypeScript.

.mjs — ES Module JavaScript

Plain JavaScript using modern import/export syntax. All scripts in this repo are .mjs: verify-contract.mjs, build-prop-map.mjs, init-ds.mjs, etc.

JavaScript plano usando sintaxis moderna import/export. Todos los scripts en este repo son .mjs: verify-contract.mjs, build-prop-map.mjs, init-ds.mjs, etc.

.css — CSS

Styling rules for HTML. Components use .module.css — same syntax but class names get hashed at build time so they cannot collide. A consumer targets components via data-* attributes, not class names.

Reglas de estilo para HTML. Los componentes usan .module.css — misma sintaxis pero los nombres de clase se hashean en tiempo de build para que no puedan colisionar. Un consumidor apunta a los componentes vía atributos data-*, no por nombres de clase.

tsconfig.json

Tells the TypeScript compiler how to behave: which files to include, how strict to be, which JS version to target. Configuration, not code. The repo has tsconfig.base.json (shared rules) and per-package overrides.

Le dice al compilador de TypeScript cómo comportarse: qué archivos incluir, qué tan estricto ser, qué versión de JS apuntar. Configuración, no código. El repo tiene tsconfig.base.json (reglas compartidas) y sobreescrituras por paquete.

vite.config.ts

Vite is the build tool and dev server. This config says where the entry point is, whether to build a library or an app, and which plugins to use.

Vite es la herramienta de build y servidor de desarrollo. Esta config dice dónde está el punto de entrada, si construir una librería o una app, y qué plugins usar.

pnpm-workspace.yaml

pnpm

A package manager — the tool that downloads and organizes the external code your project depends on. You list what you need in package.json, run pnpm install, and it downloads everything into node_modules/ while locking exact versions in pnpm-lock.yaml.

Same job as npm or yarn, but faster and uses less disk space. More importantly for this repo: pnpm handles monorepos better — packages inside the same repo can reference each other by name without publishing anywhere. Workspace is pnpm's word for this: packages/react imports @ds/tokens and pnpm resolves it to packages/tokens/ locally.

Un gestor de paquetes — la herramienta que descarga y organiza el código externo del que depende tu proyecto. Listas lo que necesitas en package.json, ejecutas pnpm install, y descarga todo en node_modules/ mientras bloquea versiones exactas en pnpm-lock.yaml.

Mismo trabajo que npm o yarn, pero más rápido y usa menos espacio en disco. Más importante para este repo: pnpm maneja mejor los monorepos — los paquetes dentro del mismo repo pueden referenciarse entre sí por nombre sin publicar en ningún lado. tokens/*.json

Source of truth for every design value. Written in DTCG. Empty until measured from Figma. Primitives reference nothing; semantics reference primitives; component slots reference semantics.

packages/tokens/build/

Compiled output. Style Dictionary writes CSS custom properties (--ds-color-fill-loud) and typed TS constants. Components read these — never the raw JSON.

<Name>.contract.json

What the component IS. Framework-agnostic. Declares anatomy, states, axes, and the token policy: which CSS channel each part exposes and which token family may supply it. A contract does not say what to use — it says which socket exists for a consumer to wire.

<Name>.react.json

React-specific binding: which HTML element renders, where the ref lands, which part absorbs className. Everything else lives in the contract.

<Name>.tsx

Component code. Uses CVA to map axis values to CSS classes. Named nodes carry data-ds-part="x" (public styling target) and className={styles.x}. Never hard-codes a token value — always var(--ds-color-fill-loud).

<Name>.module.css

Component styles. References token CSS variables. Hashed class names are the private implementation; data-* attributes are the public surface a consumer targets.

tokens/*.json

Fuente de verdad para cada valor de diseño. Escrito en DTCG. Vacío hasta que se mide desde Figma. Los primitivos no referencian nada; los semánticos referencian primitivos; los slots de componentes referencian semánticos.

packages/tokens/build/

Output compilado. Style Dictionary escribe propiedades CSS custom (--ds-color-fill-loud) y constantes TS tipadas. Los componentes leen esto — nunca el JSON crudo.

<Nombre>.contract.json

Lo que el componente ES. Agnóstico de framework. Declara anatomía, estados, ejes, y la política de tokens: qué canal CSS expone cada parte y qué familia de token puede suministrarlo. Un contrato no dice qué usar — dice qué socket existe para que un consumidor lo conecte.

<Nombre>.react.json

Binding React-específico: qué elemento HTML renderiza, dónde aterriza la ref, qué parte absorbe className. Todo lo demás vive en el contrato.

<Nombre>.tsx

Código del componente. Usa CVA para mapear valores de eje a clases CSS. Los nodos nombrados llevan data-ds-part="x" (objetivo de estilo público) y className={styles.x}. Nunca hardcodea un valor de token — siempre var(--ds-color-fill-loud).

<Nombre>.module.css

Estilos del componente. Referencia variables CSS de tokens. Los nombres de clase hasheados son la implementación privada; los atributos data-* son la superficie pública que apunta un consumidor.
